# 13/05/2026 Changes

## /scan — user confirm flow + buttons
**Files**: `discord/commands.go`, `discord/bot.go`

- `/scan` now shows "🔍 Scanning best pair… (N scanned)" instead of generic "thinking…"
- All AI scored results (trade, hold, wait) display Accept/Decline buttons
- **Accept**: trades execute immediately + TP/SL placed, hold/wait acknowledged
- **Decline**: clears result, prompts user to run `/scan` again
- Thread-safe scan state (`activeScan`) with mutex, message component handler for buttons
- Follow-up message with buttons (Discord doesn't support components on deferred edits)

## TP/SL trigger orders on Hyperliquid
**Files**: `exchange/hyperliquid.go`, `discord/commands.go`, `discord/bot.go`

- New `PlaceTriggerOrder()` method using SDK `TriggerOrderType` with `ReduceOnly: true`
- TP/SL bracket orders placed immediately after entry — visible on Hyperliquid UI
- Wired into `handleScanAccept` and `/execute` full pipeline
- Helper `placeTriggerOrders()` in `bot.go` fires both TP+SL, logs errors without failing

## Monitor — wait for fill before monitoring
**Files**: `monitor/position.go`

- `waitForFill()` polls exchange every 15s (immediate first check), up to 120 min
- `hasPositionOnExchange()` matches by pair+side against live positions
- Prevents fake "WIN/LOSS" logs when limit order hasn't filled yet
- On timeout: cleans up position record silently (no trade logged)
- Status updated to "filled" after confirmation, then monitoring begins
